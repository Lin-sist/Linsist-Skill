# 测试学习记录与交接模板 (TestLab Practice Record)

> 记录保存在本地工作区（如 `.linsist/notes/`）。严格记录真实的测试类、运行命令与结果。未运行的代码必须如实标注为“未运行/代码走读”。结构化标签仅在写入卡片时静默使用。

```markdown
# [YYYY-MM-DD] 软件测试与质量防护卡

- **当日核心主题**：<如：Mockito 外部服务模拟 / Agent 状态机非法跳转断言>
- **一句话防护价值**：<用一句话概括该测试用例保护了什么业务逻辑>
- **被测项目证据**：
  - 测试文件位置：`<仓库名> / <文件相对路径>`
  - 测试类与方法：`<类名>#<方法名>`
- **AAA 结构解析**：
  - Arrange：<准备了哪些前置状态与 Mock 数据>
  - Act：<调用了哪个业务方法或触发了什么事件>
  - Assert：<断言了什么关键返回值、状态转移或异常类型>
- **防止破坏的典型失败场景**：<如果缺少此测试，线上在什么边界下会崩盘>
- **实际执行与验证记录**：
  - 执行命令：<如：mvn test -Dtest=AgentStateMachineTest>
  - 运行结果：Passed (X ms) / Failed / 未运行 (纯推演)
  - 关键日志/断言输出：<关键终端信息>
- **卡点与排障记录**：
  - 原始报错信息：<如断言不匹配或 NullPointerException>
  - 最终定位与修复：<指明是业务逻辑 Bug 还是测试桩配置有误>
- **面试 60 秒技术自述**：<如何向面试官证明你的测试不仅仅是走过场，而是具备防御价值>
- **48h 闭卷复测设计**：
  - 建议复测日期：`YYYY-MM-DD` (48 小时后)
  - 题目 1（断言设计）：<针对某业务场景设计一组等价类与边界值用例>
  - 题目 2（排障定位）：<给出一段单测报错堆栈，分析可能诱因>
  - 复测状态：待复测 / 已通过 / 二次强化
- **下次启动第一步**：<精准到具体测试文件或场景的最小动作>
```
