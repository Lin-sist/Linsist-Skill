# Linux 实验命令与实践组织 (Lab Commands)

> **原则**：命令仅是帮助观察底层机制的窥镜。每次实验仅挑选少量最精练的命令，核心在于解释“终端输出了什么”以及“操作系统内核在背后做了什么”。

---

## 1. 核心观测与排查命令矩阵

```bash
# 进程与线程拓扑观测
ps aux                   # 查看全局进程状态、CPU/内存占用
pstree -p                # 观察父子进程树及 PID 拓扑
ps -T -p <PID>           # 观测指定进程内部所有原生轻量级线程 (LWP)
cat /proc/<PID>/status   # 深度核查进程自愿/非自愿上下文切换次数 (voluntary_ctxt_switches)

# 内存与虚拟地址空间
free -h                  # 查看物理内存、Swap、Buffer/Cache 占用
vmstat 1                 # 持续观测上下文切换 (cs)、中断 (in)、缺页异常 (si/so)
cat /proc/<PID>/maps     # 观察目标进程的代码段、堆、内存映射区、栈等 VMA 布局

# 文件系统与 I/O 句柄
lsof -p <PID>            # 列出目标进程打开的所有文件描述符 (FD)、Socket 与管道
ls -li                   # 观测文件的 inode 编号与硬链接计数
df -h && du -sh *        # 文件系统挂载点与磁盘目录空间占用

# 系统调用拦截与追踪
strace -c <command>      # 统计目标程序执行期间各类系统调用的调用次数与耗时分布
strace -p <PID> -e trace=network # 动态拦截目标进程的网络 I/O 系统调用
```

## 2. 课堂与无终端替代练习模式

在操作系统课堂或实践中调用此 Skill 时：

1. **紧扣当前知识点**：若课堂正在讲授进程调度或虚拟内存，则选择 1 个 10 分钟能看到直观输出的最小实验。
2. **预测优先于执行**：在终端回车前，必须先让学习者预测输出结果（如：“你觉得创建 10 个线程后，在 `/proc/<PID>/status` 里会看到什么变化？”）。
3. **无实验环境降级方案**：
   若身处无 Linux 机器或无法执行命令的环境，可降级采用：
   - 白板/纸笔架构手绘图（如绘制页表多级索引过程）；
   - 场景推演（如银行家算法推演安全序列）；
   - 面试攻防问答；
   - 费曼复述。
   *注：推演结论必须如实标记为“逻辑推演”，不可虚构为“已在 Ubuntu 运行通过”。*
