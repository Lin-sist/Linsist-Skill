# 用户简历与项目证据对齐检查表

本表为通用检查方法，不含作者或任何特定学习者的简历、项目审阅记录。每位用户的课程范围都从其本场提供的材料建立；没有证据时标为待核验，不能套用示例参数或类名。

| 检查项 | 需要的材料 | 对齐规则 |
| --- | --- | --- |
| 简历与目标 | 用户自己的简历或经历摘要，可选岗位 JD | 提取岗位相关机制，不因题库存在就全部安排 |
| 基础与掌握度 | 一个摸底问题、独立手写与复述 | 简历声明、仓库存在代码、用户已掌握是不同事实 |
| 项目实现 | 用户本场授权提供的代码、配置或报告 | 区分已实现、部分实现、规划、未知；不引用别人的项目口径 |
| 状态与工具 | 真实枚举、工具注册及权限边界 | 教学状态名不冒充项目枚举；参数合法不等于授权执行 |
| 记忆与上下文 | 当前检索与预算策略 | 区分召回、时间标签、字符/token 裁剪及衰减公式 |
| 引用与评测 | 指标代码、分子分母、样本与版本 | 词汇重合、语义支持、最终正确率不可互相替代 |
| 故障与反思 | 触发条件、调用次数、剩余预算 | 不从通用反思范式推断项目允许任意重试 |
| 运行证据 | 本次命令和结果、合成/真实依赖标识 | Fake LLM 只证明实验行为；本地命令通过不等于真实模型或生产验收 |
| 示例与经历 | 课程示例、独立实验、用户项目分别记录 | 新练习通过不自动加入简历项目经历 |

个人简历路径、项目映射、训练历史和设备安排应保存在用户的本地画像或独立自用技能中，不写回开源技能。对照发现冲突时，先列材料差异，再修正有证据的陈述；不擅自改用户简历或业务代码。
