# 学习记录与交接模板 (Records & Handoff Template)

> **原则**：只记录实际发生的内容与客观证据。未核验标注“未确认”，未实际运行代码/测试标注“未运行”。推测的错误原因标注为待验证。结构化标签仅在写入卡片记录时静默使用，对话中不机械复读。

---

## 1. 每日单点突破学习卡片 (Daily Note Card)

默认保存路径：`.linsist/notes/YYYY-MM-DD_<主题简写>.md`

```markdown
# [YYYY-MM-DD] <学习主题名称>

- **一句话机制速记**：<用一句话概括核心机制与底层逻辑>
- **学习者自述解释**：<记录学习者脱稿表达的关键要点>
- **费曼验收结论**：通过 / 已纠正 / 待强化
- **实践任务与代码证据**：
  - 任务目标：<如：手写二段式确认回滚逻辑 / 定位 BM25 检索评分>
  - 独立完成情况：独立编写 / 提示后完成 / 代码走读推演
  - 关联代码位置：`<仓库名> / <文件路径> / <类或方法>`
  - 实际执行状态：已运行 (Passed) / 编译通过未运行 / 未运行 (纯推演)
- **底层设计与权衡 (Why)**：<为什么这样设计？相比传统方案有什么代价与优势？>
- **典型失败与边界场景**：<遇到异常、网络超时、非法输入或并发冲突时系统如何表现？>
- **面试 60 秒高频表达**：<凝练结论 + 关键技术选型 + 核心收益与量化指标>（注：只有用户真实项目中已实现并具备代码/测试凭证的技术才能作为个人经历自述；未落地技术转为『行业通用方案对比与选型思考』）
- **原始认知偏差与纠正**：
  - 原始错误说法：<初次回答时的卡点或错误理解>
  - 正确机制解释：<纠偏后的准确认知>
- **48h / 168h 间隔复测题（闭卷）**：
  - 第 1 轮建议复测日期 (48h)：`YYYY-MM-DD`
  - 第 2 轮建议复测日期 (168h)：`YYYY-MM-DD`
  - 题目 1（概念机制）：<脱稿解释某核心概念>
  - 题目 2（边界/代码）：<手写或推演某关键逻辑>
  - 复测状态：待复测 / 第1轮已通过 / 已完全掌握
- **下次行动第一步**：<精准到 5 分钟内可启动的具体动作>
```

## 2. 跨会话交接摘要 (Handoff Summary)

当单次对话过长、切换会话或跨天接续时生成并提示保存：

```markdown
# 跨会话学习交接卡

- **已完成主题**：`<项目/模块/知识切片>`
- **已能够讲清的关键点**：`<经过费曼验收合格的内容>`
- **仍暴露薄弱的盲区**：`<需要二次练习或易混淆概念>`
- **本次踩坑与纠偏记录**：`<关键错误与纠正点>`
- **实践代码与笔记归档位置**：`<本地文件路径或 .linsist/notes/>`
- **48h 到期复测题目清单**：
  1. `<复测题 1>` (到期日: YYYY-MM-DD)
  2. `<复测题 2>` (到期日: YYYY-MM-DD)
- **下次启动第一题 / 动作**：`<明确的下一题或定位操作>`
```
