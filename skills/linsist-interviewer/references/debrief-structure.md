# 技术模拟面试复盘规范 (Debrief Structure)

> **原则**：复盘仅以本场面试中候选人的实际回答和代码为证据。不凭借主观猜想断定候选人水平，提示后答出的与独立答出的分开记录。不给出主观的 Offer 概率，只提供扎实的工程能力反馈。

---

## 复盘交付结构

```markdown
# 模拟技术一面深度复盘报告

## 1. 实际展开路线
-还原考察的主要技术分支与深挖路径（如：Agent 状态机 -> Native Function Calling -> BM25 检索原理 -> MySQL 事务隔离）。未触及的分支无需罗列。

## 2. 稳定掌握点（具备扎实工程证据）
- 列出候选人回答逻辑自洽、机制清晰、能够承受深度追问的技术点。
- 附带本场真实表现摘要（例如：“能准确说清二段式确认如何防止大模型幻觉触发危险写操作”）。

## 3. 暴露盲区与卡点（按严重程度归类）
- **核心机制理解偏差**：具体指出哪个底层原理理解倒置或概念混淆。
- **工程证据缺失**：声称已实现某项优化，但无法解释基线、指标度量方式或失败保护。
- **手写/编码实现薄弱**：语法不熟、边界条件处理遗漏、时间复杂度过高。
- **表达与逻辑结构问题**：回答冗长缺乏主线、堆砌术语但无法落地。

## 4. 本场 Top 3 核心攻坚建议 (P0)
- **P0-1**：<最需要立即补强的概念/链路> —— 原因：在同类技术面试中属于必考核心，且本场出现明确逻辑阻塞。
- **P0-2**：<次优先修复项> —— 原因：项目说服力严重不足，缺乏量化或验证支撑。
- **P0-3**：<可选第三项>

## 5. 项目说服力与表达重构建议
- **原始表达诊断**：指出候选人哪段自述存在长篇大论、重点偏移或容易被面试官抓住漏洞。
- **重构示范（20 秒结论 + 60 秒展开）**：示范如何用“业务挑战 -> 技术机制设计 -> 失败防御 -> 最终可量化效果”的模型呈现亮点。

## 6. 面试官综合评估与后续专项建议
- **正面技术信号**：本场展现出的扎实亮点与工程素养。
- **待验证/风险点**：仍未获得充分信号的技术方向。
- **后续专项训练入口**：
  - 核心机制补课与 48h 闭环：可启用 `linsist-coach`。
  - 手写代码与算法基础补强：可启用 `linsist-basics`。
  - Linux 机制推演与系统排错：可启用 `linsist-os`。
  - 测试用例与真实断言设计：可启用 `linsist-testlab`。
```
